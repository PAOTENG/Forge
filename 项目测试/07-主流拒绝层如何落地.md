# 主流拒绝层如何落到 Forge

对照 Codex / Cursor：沙箱定边界，批准是人，撤回是事后。模型口头拒绝只是第一层。

Forge 已接到工具上的实现如下。拒绝者是**代码**，错误信息以「拒绝：」开头，模型若调用了工具会看见。

---

## 四层（和主流对齐）

| 层 | 主流叫什么 | Forge 现在 |
|----|------------|------------|
| 1. 说明书 | system prompt | `INSTRUCTIONS`：别出工作区、别 force push |
| 2. 代码闸门 | sandbox / permission profile | `app/services/safety.py`，写/删/bash/git 都会跑 |
| 3. 人批准 | approval_policy | HITL；评测才 `auto_approve` |
| 4. 后悔药 | checkpoint / undo | 写前备份；人在页面点恢复。没有自动医生 |

---

## 代码闸门具体拦什么

工作区是 `order-api`（值班监控目标）时，范围是 **hotfix**：

- 只许写 `bugs.py`、`app.py`
- 改 README、测试、`active_bug.txt`、`.env` → 工具拒绝并说明原因

普通工作区是 **workspace**：

- 工作区内能写（仍不能出目录、不能写 `.env`）
- 绝对路径、`../`、C 盘绝对路径 → 拒绝

Git / bash：

- `reset --hard`、force push、rebase：git 工具拦
- 以前的漏洞：bash 在 Docker 里也能改挂载的仓库。现在 `assert_safe_bash` 先拦再 exec

自动批准**不会**关掉这些闸门。评测免的是「等人点允许」，不是「可以写 C 盘」。

## 怎么证明铁门被撞上

不经过模型，直接调函数（已进 pytest，56 passed）：

```bat

```

这才是「工具拒绝」。诱导对话那一轮证明的是「模型也愿意说不」。
