## 5. BUG-6 为什么不计成功

Agent 的补丁是把

```python
if n != 6 and qty < 1:
```

改成对所有题都拒绝 `qty < 1`。`tests/test_orders.py` 随后 3 passed。

活进程金丝雀在修后仍是 500，只是文案从 `BUG-6: total=-10.0` 变成了 `BUG-6: ValueError: qty must be >= 1`。

原因在验收器，不在“Agent 完全没改对”：

- 金丝雀用 `qty=-1` 探活。故障态期望看到错误总额；修对之后，合法实现会拒绝负数量，金丝雀照样拿不到 200。
- `test_rejects_bad_qty` 反而会在修对后变绿。这题的 pytest 和金丝雀成功方向不一致。

按事先写死的产品标准（金丝雀必须 200），本轮 **不能** 把 BUG-6 算进 pass@1。它说明的是：弱验收器会把一次合理热修打成失败。不要事后改规则把 6/7 改成 7/7。
