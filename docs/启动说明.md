# Forge 启动说明

项目根目录：克隆后的本仓库根目录

目录划分：

- `backend/` FastAPI、Alembic、agent
- `frontend/` Vue 工作台
- `infra/` Docker Compose 与沙箱镜像
- `docs/` 文档

每次开机按「每次启动」即可。conda 环境、依赖、沙箱镜像一般不用重装。

逐步讲解、端口、自检和故障表见 **[全部服务启动手册.md](全部服务启动手册.md)**。

---

## 每次启动（按顺序）

### 1. 打开 Docker Desktop

等到 Engine running。确认：

```bat
docker version
```

### 2. 启动 Postgres

```bat
cd /d <repo-root>
docker compose -f infra\docker-compose.yml up -d
```

容器名 `forge-postgres`，端口 `5432`。确认：

```bat
docker inspect --format "{{.State.Health.Status}}" forge-postgres
```

应为 `healthy`。

### 3. 确认沙箱镜像（通常不用重建）

```bat
docker images forge-runner:latest
```

没有再构建：

```bat
cd /d <repo-root>
docker build -t forge-runner:latest -f infra\sandbox\Dockerfile infra\sandbox
```

### 3.5 被监控业务（一般不用单独开）

API 启动时会自动拉起 `targets/order-api`（`:8790`），并盯着 `/canary`。当前题号在 `targets/order-api/active_bug.txt`，默认 `1`。修好一题后在落地页点「下一题」。

要把热修推到 Gitee：在 `targets/order-api` 里 `git init`（若还没有）并 `git remote add origin <gitee 仓库>`，先保证本机 `git push` 能成功。

### 4. 启动后端（终端 A，保持开着）

用 conda 环境 `forge`，不要用 `agent` 或 `base`。启动时会自动跑 Alembic 迁移。

```bat
conda activate forge
cd /d <repo-root>\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8787
```

或：

```bat
cd /d <repo-root>\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8787
```

成功标志：`Uvicorn running on http://127.0.0.1:8787`

改过根目录 `.env` 后必须重启 API。

### 5. 启动前端（终端 B，保持开着）

```bat
cd /d <repo-root>\frontend
pnpm dev
```

浏览器：**http://127.0.0.1:5173/**

第一次打开会要求创建管理员（用户名字母数字，密码至少 8 位）。之后每次要登录。管理员点标题栏「账号」可加工程师或只读账号。

同一 Wi-Fi 下手机打开 Vite 打印的 Network 地址，例如 `http://192.168.x.x:5173`。不要把手机直接指到 `:8787`。

改过后端路由或前端 `vite.config.ts` 后，两个进程都要重启。用户终端走 WebSocket，由 Vite 把 `/api` 连到 8787。

## 值班 / 企微 / 钉钉

根目录 `.env` 增加（示例见 `.env.example`）：

- `FORGE_PUBLIC_URL`：手机能打开的地址，一般是 `http://<值班机局域网IP>:5173`
- `FORGE_DUTY_WORKSPACE`：排查时挂载的仓库；空则用本 Forge 仓库
- `FORGE_DUTY_TOKEN`：告警 webhook 校验（空则跟 `FORGE_API_TOKEN`，都空则免 token）
- 企微应用：`WECOM_CORP_ID` / `WECOM_CORP_SECRET` / `WECOM_AGENT_ID`
- 钉钉自定义机器人：`DINGTALK_WEBHOOK`，加签则再填 `DINGTALK_SECRET`（只能在**电脑钉钉**建，手机没有这个入口，步骤见下）

### 钉钉自定义机器人（官方路径，必须电脑客户端）

官方文档：[创建自定义机器人](https://open.dingtalk.com/document/dingstart/custom-bot-creation-and-installation.md)、[获取 Webhook](https://open.dingtalk.com/document/orgapp/obtain-the-webhook-address-of-a-custom-robot.md)、[安全设置](https://open.dingtalk.com/document/orgapp/customize-robot-security-settings.md)。截图和步骤都是 Windows/Mac **桌面客户端**，没有手机端创建流程。

1. 装 [电脑钉钉](https://www.dingtalk.com/download)，用和手机同一账号登录。网页版一般也加不了。
2. 发起一个只要自己的群（点「发起群聊」，勾自己即可）。单聊不是群，没有机器人。
3. 打开该群 → 右上角**齿轮「群设置」**（不是手机上的 `···`）。
4. **群管理 → 机器人 → 添加机器人 → 自定义 / 自定义机器人**。旧版文案可能是「智能群助手」。
5. 名字填 `Forge`。安全设置三选一：推荐 **加签**（会得到 `SEC` 开头的密钥）；或 **自定义关键词**，关键词填 `Forge`（必须和卡片标题一致）。不要选 IP 白名单（家里公网 IP 会变）。
6. 勾选免责条款 → 完成。复制 `https://oapi.dingtalk.com/robot/send?access_token=...` 到 `.env` 的 `DINGTALK_WEBHOOK`；加签则把 `SEC...` 填进 `DINGTALK_SECRET`。不要把这两串发到聊天里。
7. 改 `.env` 后重启 API。

电脑端也没有「自定义」：有的组织关掉了新建入口。官方替代是[企业内部应用机器人](https://open.dingtalk.com/document/orgapp/the-creation-and-installation-of-the-application-robot-in-the.md)，走 AppKey + OpenAPI，**不是**这套 Webhook，Forge 目前接不上。那时先用手机浏览器直接打开 `FORGE_PUBLIC_URL`。

改 `.env` 后重启 API。落地页可点「模拟告警」「排查」。批准卡片打开 `{FORGE_PUBLIC_URL}/api/duty/card?token=`。监控接入：

```bat
curl -X POST http://127.0.0.1:5173/api/duty/alerts -H "Content-Type: application/json" -d "{\"title\":\"下单500\",\"summary\":\"order-api\",\"severity\":\"critical\"}"
```

## 怎么停

前端、API 终端各 Ctrl+C。停数据库：

```bat
cd /d <repo-root>
docker compose -f infra\docker-compose.yml stop
```

不要用 `docker compose down -v`（会删数据卷）。
