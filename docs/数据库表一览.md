# Forge 数据库表一览

引擎：**PostgreSQL**（Docker 容器 `forge-postgres`，端口 `5432`）。  
业务 ORM 表 **12 张**。另有 Alembic 自己的 **`alembic_version`**（1 张），一般不当业务表用。

下面用**同一条值班故事**串示例数据，便于对照外键：

> 工程师 `engineer` 登录后，watchdog 因 BUG-5 金丝雀失败进收件箱。  
> 点「排查」开会话 `sess-02`，模型要 `write_file` 改 `bugs.py`，人批准后继续。

固定编号（示例，不是库里的真实 UUID）：

| 角色 | 示例 id |
|---|---|
| 用户 | `user-01` |
| 工作台会话 | `sess-02` |
| 告警 | `alert-03` |
| 用户消息 | `msg-11` |
| 助手消息 | `msg-12` |
| 审计 | `audit-21` |
| 写前备份 | `bak-31` |
| 代码切块 | `chunk-41` |
| 自定义模型 | `cmod-51` |
| 登录 cookie | `login-tok-aaa` |
| 批准卡 token | `a1b2c3d4e5f6abcd` |

---

## 总览

| # | 表名 | ORM 类 | 干什么 |
|---|---|---|---|
| 1 | `sessions` | `SessionRow` | 一次工作台对话（路径、模型、mode） |
| 2 | `messages` | `MessageRow` | 给人看的聊天气泡 / 工具日志 |
| 3 | `agent_states` | `AgentStateRow` | 给模型续聊的结构化历史 + 待批工具 |
| 4 | `audits` | `AuditRow` | 谁点了允许 / 拒绝 |
| 5 | `file_backups` | `FileBackupRow` | 改文件前快照的元数据（正文在磁盘） |
| 6 | `file_chunks` | `FileChunkRow` | 工作区切块，给 `search_code` |
| 7 | `duty_alerts` | `DutyAlertRow` | 值班收件箱 |
| 8 | `duty_pending` | `DutyPendingRow` | 批准卡短 token |
| 9 | `custom_models` | `CustomModelRow` | 用户自己加的模型菜单项 |
| 10 | `installed_plugins` | `InstalledPluginRow` | 工作台插件是否启用 |
| 11 | `users` | `UserRow` | 本地账号 |
| 12 | `auth_sessions` | `AuthSessionRow` | 登录态（cookie） |
| — | `alembic_version` | 无业务模型 | 当前迁移版本号 |

关系（简化）：

```text
users 1──n auth_sessions
sessions 1──n messages / audits / file_backups
sessions 1──1 agent_states
sessions 1──n duty_pending
duty_alerts n──0..1 sessions   （session_id 可空）
file_chunks 按 workspace_key，不直接外键 sessions
```

---

## 1. `sessions`

**作用：** 一次「打开工作区 + 跟 Agent 说话」。排查或工作台「新会话」插入。聊天、状态、备份都挂 `id`。

| 字段 | 类型（概念） | 说明 |
|---|---|---|
| `id` | 字符串 PK | UUID，SSE / Runtime 的 key |
| `title` | 字符串 | 侧栏标题 |
| `workspace_path` | 文本 | 工具读写的根目录 |
| `model` | 字符串 | 本会话锁定的模型 id |
| `mode` | 字符串 | `plan` 只读 / `build` 可写 |
| `created_at` | 时间 | 创建 |
| `updated_at` | 时间 | 更新 |

**示例（点排查之后）：**

| id | title | workspace_path | model | mode | created_at |
|---|---|---|---|---|---|
| `sess-02` | 值班 · order-api 金丝雀失败 · BUG-5 | `targets/order-api` | `deepseek/deepseek-reasoner` | `build` | 2026-09-07 17:20:00+08 |

---

## 2. `messages`

**作用：** 工作台里看得见的气泡。用户原话、模型回答、工具摘要。  
给模型续跑用的是 `agent_states.input_items`，两套并行。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 PK | UUID |
| `session_id` | 外键 → `sessions.id` | 属于哪一次对话 |
| `role` | 字符串 | `user` / `assistant` / `system` |
| `kind` | 字符串 | 空=普通文本；`tool`=工具日志 |
| `content` | 文本 | 正文 |
| `created_at` | 时间 | 创建 |

**示例：**

| id | session_id | role | kind | content | created_at |
|---|---|---|---|---|---|
| `msg-11` | `sess-02` | `user` | （空） | 你是值班热修助手。当前激活 BUG-5。… | 17:20:05 |
| `msg-12` | `sess-02` | `assistant` | （空） | 定位到 `bugs.py` 的 `apply_bug_5`，准备最小热修。 | 17:21:10 |
| `msg-13` | `sess-02` | `assistant` | `tool` | write_file path=bugs.py | 17:21:40 |

---

## 3. `agent_states`

**作用：** 每个会话一行，主键就是 `session_id`。存 OpenAI Agents SDK 的 `input_items` JSON，API 重启后还能 `load_input_items`。`pending_*` 让刷新后还能画出「等待批准」条。

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | PK，外键 → `sessions.id` | 一对一 |
| `input_items` | JSONB 数组 | SDK 历史 item |
| `pending_tool` | 文本 | 卡住的工具名，无则空 |
| `pending_arguments` | 文本 | 该工具参数 JSON |
| `updated_at` | 时间 | 上次保存 |

**示例（卡在 HITL）：**

| session_id | pending_tool | pending_arguments | updated_at |
|---|---|---|---|
| `sess-02` | `write_file` | `{"path":"bugs.py","content":"..."}` | 17:21:40 |

`input_items` 示例（同一行里的 JSON，不是另一张表）：

```json
[
  {"role": "user", "content": "你是值班热修助手。当前激活 BUG-5。…"},
  {"type": "function_call", "name": "read_file", "arguments": "{\"path\":\"bugs.py\"}"},
  {"type": "function_call_output", "output": "def apply_bug_5(...): ..."}
]
```

---

## 4. `audits`

**作用：** 一次 HITL 决策。事后可查「谁批准了」。`tool_name` 在写入时固定为 `approval`；具体工具名在 pending / 参数里。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 PK | UUID |
| `session_id` | 外键 → `sessions.id` | 哪一次对话 |
| `tool_name` | 字符串 | 此处为 `approval` |
| `arguments` | 文本 | scope：`once` 或 `session` |
| `decision` | 字符串 | `allow` / `deny` |
| `actor` | 字符串 | 用户名，卡片则为 `card` |
| `created_at` | 时间 | 创建 |

**示例：**

| id | session_id | tool_name | arguments | decision | actor | created_at |
|---|---|---|---|---|---|---|
| `audit-21` | `sess-02` | `approval` | `once` | `allow` | `engineer` | 17:22:01 |

---

## 5. `file_backups`

**作用：** 一次写/删之前的快照**指针**。原文在磁盘 `data/backups/{session_id}/{id}/`，表里只记路径和过期时间。默认约 7 天，watchdog 每小时清过期行。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 PK | 也是磁盘子目录名 |
| `session_id` | 外键 → `sessions.id` | 哪一次对话 |
| `rel_path` | 字符串 | 相对工作区，如 `bugs.py` |
| `action` | 字符串 | `write` / `delete` |
| `existed` | 布尔 | 改之前文件是否已存在 |
| `actor` | 字符串 | 谁触发 |
| `model` | 字符串 | 当时模型 |
| `summary` | 文本 | diff 摘要或「覆盖 N 字符」 |
| `blob_dir` | 字符串 | 磁盘目录 |
| `created_at` | 时间 | 创建 |
| `pushed_at` | 时间，可空 | git push 成功时刻 |
| `expires_at` | 时间 | 过期 |
| `restored_at` | 时间，可空 | 回退时刻 |

**示例：**

| id | session_id | rel_path | action | existed | actor | model | blob_dir | expires_at |
|---|---|---|---|---|---|---|---|---|
| `bak-31` | `sess-02` | `bugs.py` | `write` | true | `engineer` | `deepseek/deepseek-reasoner` | `data/backups/sess-02/bak-31` | 2026-09-14 17:22:00+08 |

`summary` 可能是一小段 unified diff，此处省略。

---

## 6. `file_chunks`

**作用：** 把工作区文件切成约 80 行一块，供 `search_code` 做 ILIKE 检索。`embedding` 列预留 1024 维，当前多为 `NULL`。  
`workspace_key` 是工作区绝对路径的 sha256 前 32 位。`(workspace_key, rel_path, chunk_index)` 联合唯一。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 PK | UUID |
| `workspace_key` | 字符串，索引 | 工作区指纹 |
| `rel_path` | 文本 | 相对路径 |
| `chunk_index` | 整数 | 该文件第几块，从 0 |
| `content` | 文本 | 块正文 |
| `embedding` | vector(1024)，可空 | 未接 embedding 服务时为 NULL |
| `created_at` | 时间 | 创建 |

**示例：**

| id | workspace_key | rel_path | chunk_index | content | embedding |
|---|---|---|---|---|---|
| `chunk-41` | `a3f1c8e0…`（32 位 hex） | `bugs.py` | 0 | `def apply_bug_5(order): …` | `NULL` |
| `chunk-42` | 同上 | `app.py` | 0 | `@app.get("/canary") …` | `NULL` |

## 7. `duty_alerts`

**作用：** 收件箱。watchdog / webhook / 模拟告警插入。列表默认不显示 `resolved`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 PK | UUID |
| `title` | 字符串 | 标题，watchdog 带 `· BUG-n` |
| `summary` | 文本 | 一句话 |
| `service` | 字符串 | 如 `order-api` |
| `severity` | 字符串 | `critical` / `warning` 等 |
| `source` | 字符串 | `watchdog` / `webhook` / `demo` / `alertmanager` |
| `stack` | 文本 | 金丝雀 body / 堆栈 |
| `link` | 文本 | 如 `/canary` URL |
| `status` | 字符串 | `open` / `acked` / `investigating` / `resolved` |
| `session_id` | 外键，可空 | 点排查后挂上 |
| `assigned_to` | 字符串 | 指派给谁 |
| `acked_by` | 字符串 | 签收人 |
| `acked_at` | 时间，可空 | 签收时间 |
| `created_at` | 时间 | 创建 |

**示例（已点排查）：**

| id | title | service | severity | source | status | session_id | assigned_to | acked_by |
|---|---|---|---|---|---|---|---|---|
| `alert-03` | order-api 金丝雀失败 · BUG-5 | `order-api` | `critical` | `watchdog` | `investigating` | `sess-02` | `engineer` | `engineer` |

| link | created_at |
|---|---|
| `http://127.0.0.1:8790/canary` | 2026-09-07 17:18:04+08 |

`stack` 示例：`{"ok": false, "status_code": 500, "body": "BUG-5: ..."}`（实际可能是金丝雀响应正文）。

## 8. `duty_pending`

**作用：** 钉钉/企微批准卡上的短 token。发卡时插入，点完允许/拒绝后**删除**。API 重启后内存字典会空，仍可靠这张表对上 `session_id`（HITL 内存对象仍可能过期）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | 字符串 PK | 约 16 位 hex |
| `session_id` | 外键 → `sessions.id` | 哪一次对话 |
| `tool` | 字符串 | 如 `write_file` |
| `arguments` | 文本 | 参数摘要 |
| `created_at` | 时间 | 创建 |

**示例（尚未点允许）：**

| token | session_id | tool | arguments | created_at |
|---|---|---|---|---|
| `a1b2c3d4e5f6abcd` | `sess-02` | `write_file` | `{"path":"bugs.py"}` | 17:21:40 |

点完后这一行被删掉，表里不再有这张卡。

## 9. `custom_models`

**作用：** 右上角模型菜单里用户自增的一条。真正发请求仍要 `.env` 里有对应 Key。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 PK | UUID |
| `provider` | 字符串 | 菜单分组，默认 `custom` |
| `label` | 字符串 | 给人看的名字 |
| `model_id` | 字符串 | LiteLLM 用的 id |
| `created_at` | 时间 | 创建 |

**示例：**

| id | provider | label | model_id | created_at |
|---|---|---|---|---|
| `cmod-51` | `deepseek` | 我的 Reasoner | `deepseek/deepseek-reasoner` | 2026-09-01 10:00:00+08 |

## 10. `installed_plugins`

**作用：** 工作台查看器（md/docx/xlsx 等）是否启用。**不是** Agent 的 17 个工具。主键就是插件 id。

| 字段 | 类型 | 说明 |
|---|---|---|
| `plugin_id` | 字符串 PK | 如 `markdown` |
| `enabled` | 布尔 | 是否启用 |
| `installed_at` | 时间 | 安装/写入时间 |

**示例：**

| plugin_id | enabled | installed_at |
|---|---|---|
| `markdown` | true | 2026-09-06 09:00:00+08 |
| `docx` | true | 2026-09-06 09:00:00+08 |

## 11. `users`

**作用：** 值班机本地账号。首次打开网页创建管理员。无 SSO。机器 Token（`FORGE_API_TOKEN`）不走这张表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 PK | UUID |
| `username` | 字符串，唯一 | 登录名 |
| `password_hash` | 文本 | 哈希，不是明文 |
| `role` | 字符串 | `admin` / `engineer` / `viewer` |
| `display_name` | 字符串 | 显示名 |
| `created_at` | 时间 | 创建 |

**示例：**

| id | username | password_hash | role | display_name | created_at |
|---|---|---|---|---|---|
| `user-01` | `engineer` | `$2b$12$……`（bcrypt，此处省略） | `admin` | 值班员 | 2026-09-06 09:10:00+08 |

## 12. `auth_sessions`

**作用：** 浏览器 cookie 对应的服务端登录态。过期后 `require_user` 视为未登录。

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | 字符串 PK | cookie 值 |
| `user_id` | 外键 → `users.id` | 谁 |
| `expires_at` | 时间 | 过期 |
| `created_at` | 时间 | 登录时刻 |

**示例：**

| token | user_id | expires_at | created_at |
|---|---|---|---|
| `login-tok-aaa` | `user-01` | 2026-09-14 17:00:00+08 | 2026-09-07 17:00:00+08 |

**作用：** 记录当前迁移脚本版本，保证表结构跟上模型。不是 Agent 业务。

| 字段 | 类型 | 说明 |
|---|---|---|
| `version_num` | 字符串 | 如 `0006` 对应文件前缀 |

**示例：**

| version_num |
|---|
| `0006_file_backups` 或迁移里实际写入的版本号 |

## 故事对齐：这些行如何同时出现

1. `engineer` 登录 → `users` + `auth_sessions`  
2. 金丝雀红 → 插入 `duty_alerts`（`alert-03`，status=`open`）  
3. 点排查 → 插入 `sessions`（`sess-02`），告警 `status=investigating`，`session_id=sess-02`；后台写入 `file_chunks`  
4. 发排查稿 → `messages` 用户行；Runtime 写入 `agent_states`  
5. 要 `write_file` → `file_backups` 一行；`duty_pending` 一张卡；`agent_states.pending_tool=write_file`  
6. 点允许 → 插入 `audits`，**删除** `duty_pending` 该 token；继续跑后 `messages` 多一条助手回复  

金丝雀变绿时，watchdog 把 `duty_alerts.status` 改成 `resolved`（本文件路由 `resolve_alert` 是人手关，效果相同字段）。

## 不在 Postgres 里的东西

| 位置 | 说明 |
|---|---|
| `data/preferred_model.txt` | 默认模型，不是表 |
| `data/backups/` | 快照文件正文 |
| `targets/order-api/active_bug.txt` | 当前题号 |
| 进程内存 `_last_key` / `pending_tokens` | watchdog 冷却、批准卡内存映射 |

读代码时：表结构看 `backend/app/models/`，迁移看 `backend/alembic/versions/`。
