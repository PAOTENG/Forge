# Forge：把所有服务全部打开（详细手册）

项目根目录：克隆后的本仓库根目录  
Python 环境：**必须**用 conda 环境 `forge`，不要用 `base` 或名为 `agent` 的环境。

本文默认用 **PowerShell**。每一条命令下面都有说明。`#` 开头的是解释，**不要**当成要执行的指令。

更短的清单见 [启动说明.md](启动说明.md)。功能边界见 [功能说明.md](功能说明.md)。

---

## 1. 「全部服务」到底有哪些

开机后你要让下面这些都活着。有的是你手动开，有的是 **后端一启动就自动带上**。

| 服务 | 谁启动 | 端口 / 名字 | 干什么 |
|---|---|---|---|
| Docker Desktop | 你手动打开软件 | 本机引擎 | Postgres、会话沙箱都靠它 |
| Postgres | 你执行 compose | 容器 `forge-postgres`，本机 `5432` | 会话、告警、agent_states 等 |
| 沙箱镜像 `forge-runner` | 一般已有；没有再 build | 镜像，还不是容器 | 点排查后才会 `docker run` 出笼子 |
| Forge API | 你开「终端 A」 | `127.0.0.1:8787` | Agent、值班接口、SSE |
| 数据库迁移 Alembic | API 启动时自动 | 无端口 | 把表结构升到最新 |
| 演示业务 order-api | API 启动时自动（`FORGE_TARGET_AUTOSTART=true`） | `127.0.0.1:8790` | 带 bug 的下单服务，金丝雀 `/canary` |
| Watchdog 雷达 | API 启动时自动（`FORGE_WATCHDOG=true`） | 无独立端口 | 每约 8 秒打金丝雀，红了写收件箱 |
| Vue 工作台 | 你开「终端 B」 | `127.0.0.1:5173` | 浏览器值班台；`/api` 被代理到 8787 |

**不会**在「全部开启」时自动出现的：

- 名为 `forge-xxxxxxxx` 的沙箱容器：要等你 **点排查 / 新建会话** 才会 `ensure`
- 钉钉 / 企微：只是推送通道，不配也能用网页

浏览器请打开 **http://127.0.0.1:5173/** ，不要只用 8787（手机更不要直连 8787）。

## 2. 第一次在这台电脑上（只需做一次）

已经做过的步骤以后开机 **跳过**，从第 3 节「每次开机」开始。

### 2.1 软件

1. 安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)，勾选 WSL2，装完打开并等到 Engine running。  
2. 安装 Anaconda / Miniconda，并已有 conda 环境 `forge`。  
3. 安装 Node.js（前端 `pnpm` 需要），以及 pnpm：`npm install -g pnpm`。  
4. 项目根有 `.env`（可从 `.env.example` 复制）。至少填一个模型 Key，热修演示常用：

```env
DEEPSEEK_API_KEY=你的key
DATABASE_URL=postgresql+asyncpg://forge:forge@127.0.0.1:5432/forge
FORGE_TARGET_AUTOSTART=true
FORGE_WATCHDOG=true
```

### 2.2 第一次装 Python / 前端依赖

```powershell
# 进入 conda 环境 forge（路径按你机器上的实际 env）
conda activate forge

# 进入项目根
cd <repo-root>

# 安装后端依赖（FastAPI、Agents SDK、docker SDK 等）
python -m pip install -r backend\requirements.txt

# 进入前端目录并安装 node 包（只要做过一次，日常不必重复）
cd frontend
pnpm install
```

### 2.3 第一次确认 Docker 能跑

```powershell
# 客户端、服务端版本都能显示，说明 Desktop 已连上引擎
docker version

# 跑通一个官方测试容器，跑完自动删除
docker run --rm hello-world
```

## 3. 每次开机：按这个顺序开（共 2 个常驻终端）

请 **严格按 1→2→3→4→5**。Postgres 还没 healthy 就开 API，迁移和登录会失败。

需要 **两个 PowerShell 窗口一直开着**：终端 A = 后端，终端 B = 前端。Docker Desktop 是图形程序，不是终端里的常驻命令。

---

### 步骤 1：打开 Docker Desktop

开始菜单打开 **Docker Desktop**，等到左下角 Engine running（不要只安装不打开）。

```powershell
# 确认 docker 命令可用
docker version
```

若这里报错，后面 Postgres、沙箱全部免谈。

---

### 步骤 2：启动 Postgres（数据库）

```powershell
# 进入项目根（compose 文件在 infra 下）
cd <repo-root>

# -f 指定 compose 文件；up 创建/启动服务；-d 后台跑，不占用这个窗口
docker compose -f infra\docker-compose.yml up -d
```

容器名是 `forge-postgres`，把容器内 5432 映射到你电脑的 5432。账号密码库名都是 `forge`（见 `infra/docker-compose.yml`）。数据在 Docker 卷 `newagentproject_forge_pg` 里，关电脑不会丢。

刚启动可能还在做健康检查，等几秒再查：

```powershell
# 打印容器健康状态，期望是 healthy（不是 starting）
docker inspect --format "{{.State.Health.Status}}" forge-postgres
```

`{{.State.Health.Status}}` 是 Docker 模板，取出「健康检查结果」。不是 PowerShell 变量。

还在 `starting` 就隔几秒再执行同一句。一直失败则：

```powershell
# 看数据库容器日志，排查起不来的原因
docker logs forge-postgres
```

---

### 步骤 3：确认沙箱镜像（通常不用重建）

会话沙箱用的镜像叫 `forge-runner:latest`。日常开机 **有这个镜像即可**，不必每次 build。点排查时才会用它 `docker run` 出容器。

```powershell
# 列出本地是否已有 forge-runner:latest
docker images forge-runner:latest
```

表格里没有 `forge-runner` 再编（要几分钟）：

```powershell
cd <repo-root>

# -t 镜像标签；-f Dockerfile 路径；最后的 infra\sandbox 是 build 上下文
docker build -t forge-runner:latest -f infra\sandbox\Dockerfile infra\sandbox
```

---

### 步骤 4：启动后端 API（终端 A，不要关）

order-api（8790）和 watchdog **不要单独开**，它们挂在 API 的 lifespan 上：迁移 → `start_target` → `start_watchdog`。

**方式一（先 activate）：**

```powershell
# 激活 forge 环境，提示符前应出现环境名
conda activate forge

# 必须在 backend 目录，uvicorn 才能找到包 app
cd <repo-root>\backend

# 启动 FastAPI：只监听本机 8787
python -m uvicorn app.main:app --host 127.0.0.1 --port 8787
```

**方式二（不 activate，直接点 python.exe）：**

```powershell
cd <repo-root>\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8787
```

成功时终端出现类似：

```text
Uvicorn running on http://127.0.0.1:8787
```

同时会发生：

1. Alembic `upgrade head`（建/改表）  
2. 若 `.env` 里 `FORGE_TARGET_AUTOSTART=true`：拉起 `targets/order-api`（uvicorn `:8790`）  
3. 若 `FORGE_WATCHDOG=true`：后台每约 8 秒打 `http://127.0.0.1:8790/canary`

改过项目根 `.env` 后必须 **Ctrl+C 停掉再重新跑** 上面的 uvicorn，否则配置还是旧的。

另开窗口检查 API 和金丝雀（可选用 curl 或浏览器）：

```powershell
# Forge API 健康检查，应返回 JSON（含 ok 一类字段）
curl http://127.0.0.1:8787/api/health

# 演示业务是否在听 8790（进程活着）
curl http://127.0.0.1:8790/health

# 金丝雀：当前若是故意埋的 BUG，经常是 500，这是预期，不是 API 没起来
curl http://127.0.0.1:8790/canary
```

没有 curl 时用：

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/health
Invoke-RestMethod http://127.0.0.1:8790/health
```

当前激活题号在文件 `targets/order-api/active_bug.txt`。

---

### 步骤 5：启动前端（终端 B，不要关）

**新开一个 PowerShell**，不要占用终端 A。

```powershell
# 进入 Vue 项目
cd <repo-root>\frontend

# 开发服务器，默认 5173；把浏览器的 /api 转到 8787
pnpm dev
```

成功时会出现 `Local: http://127.0.0.1:5173/`。

浏览器打开：**http://127.0.0.1:5173/**

- 库里还没有用户：先走「首次启用」，用户名用字母数字，密码至少 8 位。  
- 之后每次打开要登录。管理员可在标题栏「账号」里加工程师或只读账号。

同一 Wi-Fi 下用手机：看终端 B 打印的 Network 地址（如 `http://192.168.x.x:5173`）。**不要**让手机访问 `:8787`。

## 4. 开齐之后你应该看到什么

| 检查 | 期望 |
|---|---|
| Docker Desktop | Engine running |
| `docker ps` | 有 `forge-postgres`（healthy） |
| 终端 A | Uvicorn 8787，不要报数据库连不上 |
| `http://127.0.0.1:5173/` | 能打开工作台 / 登录 |
| `http://127.0.0.1:8790/health` | 业务进程在 |
| 值班收件箱 | 若 canary 红，过一会儿可能出现 `BUG-n` 纸条 |

点「排查」之后，`docker ps` 里才可能多一个 `forge-` 开头的沙箱容器。这不是开机必有项。

## 5. 端口一览（避免冲突）

| 端口 | 进程 |
|---|---|
| 5432 | Postgres 容器映射到本机 |
| 8787 | Forge FastAPI |
| 5173 | Vite 前端 |
| 8790 | order-api（API 自动拉起） |

被占用时，先关掉旧的 uvicorn / pnpm / 其它占用该端口的程序。

---

## 6. 怎么停

1. 终端 B（前端）：焦点在窗口里 **Ctrl+C**  
2. 终端 A（API）：**Ctrl+C**（watchdog 会停；order-api 一般随 `start_target` 的子进程，若仍占 8790 需在任务管理器结束对应 python）  
3. 数据库（可选，明天还要用可不停）：

```powershell
cd <repo-root>

# 停止容器，数据卷保留
docker compose -f infra\docker-compose.yml stop
```

**不要**用 `docker compose down -v`：`-v` 会删数据卷，会话和告警会没。

Docker Desktop 可从托盘退出；完全退出后 Postgres 也会停。

## 7. 每天不用重复做的

```powershell
conda activate forge
cd <repo-root>
python -m pip install -r backend\requirements.txt
cd frontend
pnpm install
```

只有依赖变了（别人改了 `requirements.txt` / `package.json`）才再跑。

沙箱镜像、conda 环境也不用每天重建。

## 8. 常见失败

| 现象 | 处理 |
|---|---|
| `docker version` 失败 | 先开 Docker Desktop，等 Engine running |
| API 报连接 Postgres 失败 | 等 `forge-postgres` 变成 `healthy` 再启 uvicorn |
| 8787 端口占用 | 关掉旧的 API 窗口，或查谁占用 8787 |
| 5173 能开但接口全挂 | 终端 A 没开，或 Vite 代理不到 8787 |
| 点排查沙箱 500 | Desktop 没开，或没有 `forge-runner` 镜像（做步骤 3） |
| 模型不说话 | `.env` 没 Key，或改完 `.env` 没重启 API |
| 用了 `conda activate base` | 依赖不齐；改回 `envs\forge` |

## 9. 钉钉 / 企微（可选，不算「进程」）

网页值班不依赖它们。要手机卡片时，在 `.env` 填 `FORGE_PUBLIC_URL`、`DINGTALK_WEBHOOK` 等（模板见 `.env.example`），然后 **重启 API**。钉钉自定义机器人必须在 **电脑钉钉客户端** 的群里添加，步骤见 [启动说明.md](启动说明.md) 里「值班 / 企微 / 钉钉」。

## 10. 一张总流程图

```text
开机
  → 打开 Docker Desktop
  → docker compose up -d          Postgres :5432
  → （可选）确认 forge-runner 镜像
  → 终端 A：uvicorn :8787
        → Alembic 迁移
        → start_target            order-api :8790
        → start_watchdog          打 /canary
  → 终端 B：pnpm dev              工作台 :5173
  → 浏览器 http://127.0.0.1:5173/

之后点「排查」才：
  → sandbox_manager.ensure        沙箱容器 forge-xxxx
```

按第 3 节五个步骤做完，本机 Forge 全套服务即已打开。
